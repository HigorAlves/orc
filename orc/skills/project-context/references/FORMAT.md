# project-context.md — format reference

The per-line rubric and a worked example. Read this when generating or reviewing a context file; the spine and the size cap live in `SKILL.md`.

## The per-line rubric

Every line must pass all four:

1. **Project-specific.** A model that has never seen this repo would get it wrong.
2. **Actionable.** It tells an agent what to do, not what to know.
3. **Load-bearing.** Violating it produces a real defect, a failed gate, or a review comment.
4. **Current.** It describes the code as it is today, not as someone intends it.

Fail any one → cut it.

### Cut these

| Line | Why it fails |
|---|---|
| "Write clear, maintainable code." | Not project-specific, not actionable. |
| "Use TypeScript strict mode." | Already in `tsconfig.json` — the compiler enforces it. |
| "We value good test coverage." | Not actionable. |
| "The API layer handles HTTP requests." | Documentation, not a directive. Belongs in `/orc:onboard` output. |
| "Prefer `const` over `let`." | Universal practice; the linter already owns it. |

### Keep these

| Line | Why it passes |
|---|---|
| "Tests live beside the source as `*.test.ts`. A `__tests__/` dir is a mistake — the vitest include glob ignores it." | Specific, actionable, and the failure mode is silent. |
| "`src/db/schema.ts` is generated by `pnpm db:pull`. Hand edits are overwritten." | Landmine; nothing in the file says so. |
| "Errors cross the service boundary as `Result<T, AppError>`, never thrown. Throwing bypasses the error middleware." | Chosen idiom where another is reasonable. |
| "Every route handler needs a matching entry in `src/routes/manifest.ts` or it 404s at runtime, not at build." | Load-bearing and surprising. |
| "React 19: `use()` is available. Do not add `@tanstack/react-query` — it was removed deliberately, see ADR-0012." | Version-dependent idiom + a rejected pattern with a pointer. |

## Worked example

```markdown
---
generated: 2026-08-27
generator: /orc:context generate
stack_fingerprint: 4f2ab9c1
---

# Project context

<!-- Agent directives. Read before writing code in this repo. -->

## Stack & versions

- TypeScript 5.6, Node 22, pnpm workspaces (`packages/*`). Never `npm`/`yarn` — the lockfile is pnpm-only.
- React 19 + Next 15 App Router. Server Components by default; `"use client"` is opt-in and reviewed.
- PostgreSQL 16 via Drizzle. No ORM lazy-loading — every query is explicit.

## Critical rules

- `pnpm verify` must pass before any commit. It runs tsc, eslint, and vitest; CI runs nothing else.
- Public package exports go through `packages/<name>/src/index.ts`. Deep imports across packages break the build graph.
- Never edit `packages/db/src/schema.ts` — it is generated by `pnpm db:pull`.

## Patterns to follow

- Errors cross a service boundary as `Result<T, AppError>` (`packages/core/src/result.ts`), never thrown. Canonical example: `packages/api/src/users/get-user.ts`.
- New routes need an entry in `apps/web/src/routes/manifest.ts`, or they 404 at runtime rather than failing the build.
- Feature flags read from `packages/flags` at module scope, not per-render.

## Patterns to avoid

- Do not add a client-side data-fetching library. `@tanstack/react-query` was removed in favour of RSC + server actions — see ADR-0012.
- Do not introduce barrel files inside a package. They defeat tree-shaking here; measured 40 KB regression.

## Testing conventions

- vitest. Tests live beside the source as `*.test.ts`. A `__tests__/` dir is silently excluded by the include glob.
- Integration tests need a live PG: `pnpm db:test:up` first. They are tagged `describe.concurrent` and must stay isolation-safe.
- Green means `pnpm verify` exits 0. A passing test file alone is not green.

## Known landmines

- `apps/web/next.config.mjs` load order matters — the Sentry plugin must wrap last or source maps upload empty.
- `packages/db/migrations/` is append-only. Editing an applied migration corrupts the drift check.
```

That example is 38 lines of body. Most repos land between 30 and 90. Approaching 150 is a signal that documentation has crept in — the `/orc:onboard` knowledge files are where prose belongs.

## Frontmatter fields

| Field | Meaning |
|---|---|
| `generated` | ISO date of the last full generate or refresh. |
| `generator` | `/orc:context generate`, `/orc:context refresh`, or `manual`. |
| `stack_fingerprint` | Short sha over the sorted dependency-manifest set. A mismatch means the stack moved and a refresh is due. |

## Preserved regions

`/orc:context refresh` never rewrites:

- any line carrying a `<!-- human -->` marker;
- everything under a `## Notes` heading.

Put anything hand-authored that must survive regeneration in one of those two places.
