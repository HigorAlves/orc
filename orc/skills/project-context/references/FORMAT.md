# project-context.md format

The per-line rubric and a worked example. Spine and cap live in `SKILL.md`.

## Per-line rubric

A line stays only if it passes all four tests.

1. Project-specific: a model new to the repo would get it wrong.
2. Actionable: it says what to do.
3. Load-bearing: breaking it causes a defect, a failed gate or a review comment.
4. Current: it describes the code today.

## Cut

- "Write clear, maintainable code." Universal.
- "Use TypeScript strict mode." The compiler already enforces it.
- "The API layer handles HTTP requests." Documentation, not a directive.

## Keep

- "Tests live beside the source as `*.test.ts`. The vitest glob ignores `__tests__/`."
- "`src/db/schema.ts` is generated by `pnpm db:pull`. Hand edits are overwritten."
- "Errors cross the service boundary as `Result<T, AppError>`. Throwing bypasses the error middleware."

## Worked example

```markdown
---
generated: 2026-10-23
generator: /orc:context generate
---

# Project context

<!-- Agent directives. Cap: 150 lines / 6 KB. Critical rules are binding: a slice that needs to break one escalates. -->

## Stack & versions

- TypeScript 5.6, Node 22, pnpm workspaces. Never npm or yarn.

## Commands

- Test: `pnpm test`. Lint: `pnpm lint`. Typecheck: `pnpm tsc --noEmit`.

## Critical rules

- `pnpm verify` passes before any commit. CI runs nothing else.
- Cross-package imports go through `packages/<name>/src/index.ts`.

## Patterns to follow

- New routes need an entry in `apps/web/src/routes/manifest.ts`, or they 404 at runtime.

## Patterns to avoid

- No client-side data-fetching library. See ADR-0012.

## Known landmines

- `packages/db/migrations/` is append-only. Editing an applied migration breaks the drift check.
```

## Preserved regions

Refresh never rewrites a line marked `<!-- human -->` or anything under `## Notes`.
